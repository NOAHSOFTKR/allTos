# 나린(NARIN) 개인정보 처리방침

- **문서 버전:** v0.1 (검토 초안)
- **시행일:** 미정 — 운영자 승인과 법률 검토 후 확정합니다
- **최종 수정일:** 2026년 11월 11일

> 이 문서는 아직 시행되지 않은 검토 초안입니다. `【확인 필요】`로 표시한 부분은 운영 환경 확인 또는 법률 검토가 끝나지 않은 항목이며, 확인 전에는 확정된 사실이 아닙니다.

노아소프트(대표 김정현, 이하 "**운영자**")는 Discord 서버 보안 애플리케이션 나린(NARIN, 이하 "**서비스**")을 제공하면서 처리하는 개인정보를 「개인정보 보호법」에 따라 보호하고, 그 처리 내용을 이 방침으로 알립니다.

---

## 1. 이 방침이 적용되는 범위

1. 이 방침은 운영자가 직접 운영하는 나린(NARIN, 개발명 Sentinel Core)이 처리하는 개인정보에 적용됩니다.
2. **Discord가 처리하는 정보는 이 방침의 대상이 아닙니다.** Discord 계정, 메시지, 서버 자체의 데이터는 Discord Inc.가 자신의 개인정보처리방침에 따라 처리합니다. 서비스는 Discord가 API로 전달하는 정보 가운데 아래에 적은 항목만 처리합니다.
3. **나현(NAHYUN, 개발명 Sentinel Edge)에 저장되는 정보는 이 방침의 대상이 아닙니다.** 나현은 서버 관리자가 자신의 장비와 자신의 Discord 봇 계정으로 직접 운영하는 프로그램이며, 그 안에 저장되는 기록은 해당 서버 관리자가 관리합니다. 나현이 서비스로 전송해 서비스가 저장하는 정보에는 이 방침이 적용됩니다(제9조).
4. 서비스는 Discord 서버 단위로 동작합니다. 서버 관리자뿐 아니라, 서비스 명령을 직접 쓰지 않는 서버 구성원의 정보도 그 서버에서 일어난 보안 관련 활동의 범위에서 처리됩니다.

---

## 2. 개인정보의 처리 목적

운영자는 다음 목적으로만 개인정보를 처리합니다.

1. Discord 서버의 보안 이벤트 관측과 기록, 행위자 확인
2. 서버 파괴 행위와 대량 입장(레이드)·스팸의 탐지, 사건 관리, 서버가 정한 정책에 따른 대응
3. 서버 구조의 스냅샷 저장과 복구
4. 사건 증거의 보존과 내보내기
5. 운영 명령의 권한 확인, 관리 행위의 감사 기록
6. 웹 대시보드 로그인, 초대 게이트, 웹 인증 제공(해당 기능이 제공되는 경우)
7. AI 보안 분석 제공(해당 기능이 제공되는 경우)
8. 서비스의 장애 대응, 오남용 방지, 문의와 권리 행사 요청의 처리

운영자는 서비스로 처리하는 정보를 광고나 마케팅에 이용하지 않으며, 그러한 기능을 두고 있지 않습니다.

---

## 3. 처리하는 개인정보의 항목

서비스는 이메일 주소, 전화번호, 실명, 결제 정보를 수집하지 않습니다. 사용자명, 닉네임, 프로필 사진은 데이터베이스와 로그에 기록하지 않습니다. 다만 Discord 연결에 쓰는 라이브러리가 구성원의 사용자명 등 Discord가 전달한 정보를 서비스의 메모리에 일시적으로 보관합니다.

### 3.1 기본 기능에서 처리하는 항목

| 구분 | 항목 | 수집 방법 |
| --- | --- | --- |
| 식별자 | Discord 사용자 ID, 서버 ID, 채널 ID, 역할 ID, 메시지 ID, 웹훅·초대 코드 | Discord API(게이트웨이 이벤트, 감사 로그) |
| 구성원 상태 | 봇 여부, 보유 역할 ID 목록, 타임아웃 만료 시각, 서버 입장 시각, 퇴장 시각, 계정 생성 시각(사용자 ID에서 계산), 프로필 사진 설정 여부(예/아니오), 이름 형태 해시, 입장에 쓰인 초대 코드 | Discord API |
| 감사 로그 | 실행자 ID, 대상 ID, 변경 내용, 관리자가 Discord에 입력한 사유 문구(최대 512자) | Discord API |
| 서버 구조 | 서버·채널·역할·AutoMod 규칙의 이름, 채널 주제, 권한 설정(특정 구성원을 지정한 권한 덮어쓰기의 사용자 ID 포함), AutoMod 규칙의 설정값(금칙어 목록 포함), 서버 소유자 ID | Discord API |
| 사건·대응 기록 | 행위자·대상의 사용자 ID, 위험 점수와 근거, 탐지 규칙, 실행된 조치와 결과, 사건 상태 변경 이력 | 서비스가 생성 |
| 입장 관리 기록 | 구성원별 입장 상태(미인증·인증·의심·격리), 위험 점수와 등급, 인증 시도 횟수와 결과, 상태 변경 이력과 사유 | 서비스가 생성 |
| 신고 | 신고자 ID, 신고 대상 ID, 신고된 메시지의 ID와 채널 ID, 신고 분류, 처리자 ID와 처리 메모(최대 256자) | 구성원·운영 권한자 입력 |
| 차단 목록 | 대상 사용자 ID, 사유(최대 200자), 추가한 사람의 ID, 만료 시각 | 운영 권한자 입력 |
| 운영·감사 기록 | 운영 권한자의 사용자 ID와 권한 등급, 실행한 명령과 대상, 입력한 사유, 결과 | 운영 권한자의 명령 사용 |

- **이름 형태 해시**: 사용자 이름에서 구분 기호를 없애고 숫자를 뭉친 뒤 계산한 해시값의 일부입니다. 비슷한 이름으로 한꺼번에 입장하는 계정을 묶어 보기 위한 것이며, 이름 자체는 저장하지 않습니다. 다만 비밀값 없이 계산한 해시이므로 이름을 완전히 알 수 없게 만드는 조치는 아닙니다.
- **자유 입력 문구**: 감사 로그 사유, 채널 주제, 각종 이름, 운영 권한자가 입력한 사유와 메모에는 입력한 사람이 적은 내용이 그대로 들어갑니다.

### 3.2 메시지에 관한 처리

1. 서비스는 메시지 본문, 첨부파일, 임베드를 데이터베이스나 로그에 저장하지 않습니다. 첨부파일과 임베드는 읽지 않으며, 메시지 속 링크를 외부 서비스에 조회하지 않습니다.
2. 스팸 탐지를 위해 메시지가 올라올 때 메시지 ID, 채널 ID, 작성자 ID, 멘션 수 등을 처리하며, 이 정보는 서비스의 메모리에서 일정 시간 동안만 유지됩니다.
3. 메시지 본문 접근(Discord의 Message Content 권한)은 기본적으로 꺼져 있습니다. 【확인 필요: 운영 환경에서 이 권한을 켰는지 여부】 켜져 있는 경우 서비스는 본문에서 중복·반복 여부를 판단하기 위한 해시값(지문), 링크의 해시값, 초대 코드, 길이를 계산해 메모리에서 사용하고, 본문을 데이터베이스나 로그에 저장하지 않습니다. 이 경우 Discord 연결에 쓰는 라이브러리가 최근 메시지를 서비스의 메모리에 일시적으로 보관할 수 있습니다. 【확인 필요: 메모리 보관 범위】 스팸으로 탐지된 경우에 한해 작성자 ID, 탐지 종류, 지문이 보안 이벤트로 저장됩니다. 이 지문은 비밀값 없이 계산한 해시이므로, 짧거나 흔한 문장은 지문으로부터 추측될 수 있습니다.
4. 메시지가 삭제된 경우 메시지 ID, 채널 ID, 작성자 ID(확인되는 경우)가, AutoMod가 동작한 경우 규칙 ID, 사용자 ID, 채널 ID, 메시지 ID가 보안 이벤트로 저장됩니다. AutoMod에 걸린 내용은 저장하지 않습니다.

### 3.3 웹 대시보드·초대 게이트·웹 인증 (해당 기능이 제공되는 경우)

【확인 필요: 운영 환경에서 웹 대시보드, 초대 게이트, 웹 인증을 실제로 제공하는지 여부】

| 구분 | 항목 |
| --- | --- |
| 대시보드 로그인 | Discord 사용자 ID, 관리 권한이 있는 서버의 ID와 권한 종류. Discord 로그인 권한 범위는 `identify`, `guilds`이며 이메일은 요청하지 않습니다. Discord가 발급한 접근 토큰은 저장하지 않고 확인 직후 폐기를 요청합니다. |
| 세션 | 세션 토큰의 해시값, 사용자 ID, 생성·갱신·만료 시각. IP 주소와 브라우저 정보(User-Agent)는 세션에 저장하지 않습니다. |
| 초대 게이트 | Discord 사용자 ID, 서버 ID, 판단 결과와 사유, 부여할 역할 ID. 권한 범위는 `identify`, `guilds.join`입니다. 서버가 따로 켠 경우에만 `guilds` 범위로 참여 서버 목록을 확인하며, 목록 자체는 저장하지 않고 일치한 서버의 수만 저장합니다. Discord 접근 토큰은 추가 인증이 진행되는 동안(최대 10분)만 암호화해 보관합니다. |
| 웹 인증 | 사용자 ID, 인증 방식, 시도 결과와 시각 |
| IP 주소 | 웹 대시보드는 원문을 저장하지 않고 비밀키로 계산한 해시값만 관리 감사 기록과 AI 질의 기록에 남깁니다. 같은 IP 주소는 같은 해시값이 되므로 가명 처리에 해당합니다. 요청 횟수 제한을 위해 메모리에서도 이 해시값을 사용합니다. |

### 3.4 AI 보안 분석 (해당 기능이 제공되는 경우)

요청한 운영 권한자의 사용자 ID와 권한 등급, 입력한 질문(최대 500자), 분류를 위해 붙여넣은 메시지(최대 4,000자)와 그 메시지·채널·작성자의 ID, 분석 결과, 사용량, IP 주소의 해시값을 처리합니다. 외부로 전송되는 항목은 제8조에 적습니다.

### 3.5 자동으로 생성·수집되는 정보

1. **쿠키**: 웹 대시보드가 제공되는 경우 제11조의 쿠키를 사용합니다.
2. **서버 로그**: 서비스의 동작 기록에는 서버 ID, 사용자 ID, 사건 ID, 오류 내용이 남을 수 있습니다. 증거 다운로드 요청이 거부된 경우 요청자의 IP 주소가 로그에 남습니다. 인증 토큰 등 비밀값은 로그에서 가려집니다. 다만 웹 인증 화면에서 서버 오류가 난 경우 일회용 인증 주소가 오류 로그에 남을 수 있습니다.

## 4. 처리의 법적 근거

【법률 검토 필요: 아래는 운영자가 검토 중인 근거이며, 확정되지 않았습니다】

1. 서버 관리자와 운영 권한자의 정보: 서비스 이용 계약의 이행에 필요한 처리(「개인정보 보호법」 제15조 제1항 제4호)
2. 서비스 명령을 직접 쓰지 않는 구성원의 정보: 서버와 구성원을 보안 위협에서 보호하려는 서버 관리자와 운영자의 정당한 이익을 위한 처리(같은 항 제6호)를 근거로 검토하고 있습니다. 이 근거가 인정되는 범위, 그리고 운영자가 개인정보처리자인지 서버 관리자의 수탁자인지는 법률 검토가 필요합니다.
3. 서비스는 만 14세 미만 아동을 대상으로 하지 않으며, 동의를 근거로 아동의 개인정보를 수집하는 절차를 두고 있지 않습니다. 서비스는 이용자의 나이를 수집하지 않고 Discord도 나이를 서비스에 전달하지 않으므로, 서비스가 이용자의 나이를 확인하지는 못합니다. Discord는 이용약관으로 이용자의 최소 연령을 정하고 있습니다. 【법률 검토 필요: 아동의 개인정보가 처리될 가능성에 대한 조치】

## 5. 개인정보의 처리 및 보유 기간

**서비스에는 현재 대부분의 기록을 일정 기간 뒤 자동으로 삭제하는 기능이 없습니다.** 아래 표는 현재 구현된 상태를 그대로 적은 것입니다.

| 정보 | 보유 기간(현재 구현) |
| --- | --- |
| 보안 이벤트, 감사 로그 기록, 사건·대응 기록 | 자동 삭제 없음 |
| 입장 관리 기록(구성원별 상태, 변경 이력, 인증 시도) | 자동 삭제 없음. 구성원이 서버를 떠나면 퇴장 시각을 기록하고 기록은 남습니다 |
| 신고 기록 | 자동 삭제 없음 |
| 차단 목록 | 운영 권한자가 삭제할 때까지. 만료 시각이 지나면 적용되지 않지만 기록은 남습니다 |
| 운영 권한 부여 기록 | 서버 소유자가 회수할 때까지 |
| 관리 감사 기록 | 자동 삭제 없음. 사후 변경을 막기 위해 데이터베이스에서 수정·삭제가 차단되어 있습니다 |
| 서버 스냅샷 | 새 스냅샷을 저장할 때 서버 정책(기본값: 최대 30개, 90일)을 넘는 것을 삭제합니다. 스냅샷 저장이 멈추면(서비스 제거 등) 기존 스냅샷은 기간이 지나도 남습니다. 고정한 스냅샷, 증거나 복구 계획이 참조하는 스냅샷, 사건 스냅샷은 삭제되지 않습니다 |
| 증거 패키지(파일과 내보내기 기록) | 자동 삭제 없음 |
| 증거 다운로드 링크 | 기본 10분간 유효, 1회 사용. 링크의 해시값 기록은 자동 삭제되지 않습니다 |

### AI 보안 분석에서 외부로 전송되는 내용

1. AI 보안 분석은 생성형 인공지능을 이용하는 기능입니다. 기본적으로 꺼져 있으며, 켜져 있는 경우에도 운영 권한자가 분석을 요청할 때에만 외부로 전송합니다. 서버의 모든 메시지를 자동으로 AI에 보내는 기능은 없습니다.
2. 전송 전에 Discord 사용자 ID, 채널 ID, 역할 ID 등 식별 번호는 요청마다 새로 만드는 별칭(예: `U1`, `C3`)으로 바꿉니다. 이메일 주소, IP 주소, 전화번호, 인증 토큰 형태의 문자열은 가립니다.
3. 다음 내용은 가려지지 않고 전송될 수 있습니다.
   - 사건의 종류, 시각, 횟수, 위험 점수와 근거, 조치 결과
   - 복구 관련 분석에 포함되는 역할·채널·AutoMod 규칙의 이름
   - 질의 응답 기능에서 조회되는 해당 서버의 보안 이벤트 요약, 위험 근거 설명, 신고 기록(분류·상태·대상), 스냅샷 비교 내용, 증거 패키지의 메타데이터
   - 운영 권한자가 직접 입력한 질문과, 분류를 위해 붙여넣은 메시지 본문(위 2의 형태에 해당하지 않는 이름, 주소, 링크 등은 그대로 전송됩니다)
4. 서비스는 AI 제공자에게 보낸 요청 원문과 붙여넣은 메시지 본문을 자체 데이터베이스에 저장하지 않습니다. 분석 결과와 질의 기록은 제5조에 따라 보관하며, 저장되는 분석 결과에는 붙여넣은 내용의 일부가 인용될 수 있습니다.
5. AI 제공자가 전송받은 내용을 얼마나 보관하는지, 자신의 모델 학습에 쓰는지는 그 제공자와의 계약 조건에 따릅니다. 서비스가 보내는 요청에는 보관이나 학습을 막는 별도의 설정값이 들어 있지 않습니다. 【확인 필요: 실제 제공자의 계약 조건】
6. AI의 분석 결과는 참고용이며, 구성원에 대한 조치를 자동으로 일으키지 않습니다.
7. 운영 권한자는 AI 기능에 민감정보나 고유식별정보(주민등록번호 등)를 입력하지 않아야 합니다.

## 10. 개인정보의 안전성 확보조치

운영자는 다음 조치를 적용하고 있습니다. 아래는 서비스의 소스 코드로 확인한 내용입니다.

1. **접근 권한 관리**: 운영 명령은 Discord 서버 관리 권한과 서비스의 운영 권한(열람자·운영자·관리자)을 함께 확인합니다. Discord 명령은 실행할 때마다 확인하고, 웹 대시보드는 로그인 때 확인한 Discord 권한을 최대 30분간 사용하며 서비스의 운영 권한은 요청마다 확인합니다. 중요한 변경은 한 번만 쓸 수 있는 확인 절차를 거칩니다.
2. **접속 기록**: 관리 행위는 수정·삭제할 수 없는 관리 감사 기록에 남깁니다.
3. **암호화와 해시**: 세션 토큰, 로그인 상태값, 증거 다운로드 토큰은 원문 대신 해시값만 저장합니다. 초대 게이트에서 잠시 보관하는 Discord 접근 토큰은 AES-256-GCM으로 암호화합니다. 웹 대시보드는 IP 주소를 비밀키로 계산한 해시값으로만 데이터베이스에 저장합니다. 예외로, 증거 다운로드 요청이 거부되면 접속 IP 주소가 서버 로그에 원문으로 남고, 운영자 내부 제어 서버의 인증이 실패하면 접속 IP 주소의 해시값 일부(비밀키 없이 계산)가 운영 감사 기록에 남습니다.
4. **전송 구간 보호**: 웹 대시보드의 쿠키는 HTTPS에서만 전송되도록 설정합니다. 증거 다운로드와 나현 연결용 서버는 외부에 공개할 때 TLS를 요구합니다.
5. **로그의 비밀값 가림**: 인증 토큰, 비밀번호 형태의 값은 로그에 기록되기 전에 가립니다.
6. **데이터베이스 권한 최소화**: 서비스가 쓰는 데이터베이스 계정에는 정해진 정리 대상 테이블에 대해서만 삭제 권한을 주도록 설계되어 있습니다.

데이터베이스에 저장되는 기록 자체(사용자 ID, 사유 문구 등)와 증거 패키지 파일은 서비스가 따로 암호화하지 않습니다. 【확인 필요: 운영 환경의 저장 장치 암호화, 접근 통제, 내부 관리계획 등 「개인정보의 안전성 확보조치 기준」에 따른 조치의 실제 적용 여부】

| `__Host-sentinel_lang` | 선택한 언어 기억(언어를 직접 바꾼 경우에만 설정) | 365일 |

3. 브라우저 설정에서 쿠키 저장을 거부할 수 있습니다. 거부하면 웹 대시보드에 로그인할 수 없습니다.
4. CAPTCHA가 제공되는 경우, 인증 화면에서 해당 사업자의 스크립트가 불러와지며 그 사업자가 자체 쿠키 등을 사용할 수 있습니다.

## 12. 자동화된 처리에 관한 사항

1. 서비스는 서버 관리자가 자동 대응 정책을 켠 경우, 미리 정한 규칙과 임계값에 따라 사람의 확인 없이 구성원에게 다음 조치를 할 수 있습니다.
   - 타임아웃, 위험 권한 역할 회수, 격리 역할 부여
   - 입장 시 인증 요구, 제한, 입장 격리
   - 초대 게이트에서의 입장 허용, 추가 인증 요구, 입장 거부(해당 기능이 제공되는 경우)
2. 판단에 쓰이는 주요 정보는 다음과 같습니다.
   - 짧은 시간 안의 채널·역할 삭제 등 파괴적 행위의 횟수와 Discord 감사 로그로 확인된 행위자
   - 계정 생성 시기, 프로필 사진 설정 여부, 이름 형태의 유사성
   - 해당 서버의 차단 목록 등재 여부, 이전 격리 이력, 인증 실패 횟수, 신고 수, 스팸 탐지 이력
   - 서버의 입장 급증 상태
3. 서비스는 구성원을 서버에서 차단(ban)하거나 추방(kick)하는 조치를 자동으로 하지 않습니다. AI의 분석 결과는 위 판단에 쓰이지 않습니다.
4. 조치를 받은 구성원은 해당 서버의 관리자에게, 또는 제14조의 연락처로 운영자에게 조치의 이유에 대한 설명과 사람에 의한 재검토를 요청할 수 있습니다. 서비스 안에 구성원이 직접 이의를 제기하는 기능은 없으며, 조치의 변경은 그 서버의 운영 권한자가 하거나 운영자가 내부 관리 도구로 합니다.
5. 【법률 검토 필요: 위 조치가 「개인정보 보호법」 제37조의2의 "완전히 자동화된 시스템으로 개인정보를 처리하여 이루어지는 결정"에 해당하는지, 해당한다면 기준과 절차를 어떻게 공개하고 거부·설명 요구에 누가 응할지】

## 13. 정보주체와 법정대리인의 권리와 행사 방법

1. 정보주체는 운영자에게 자신의 개인정보에 대해 열람, 정정·삭제, 처리정지를 요구할 수 있고, 동의에 따라 처리되는 정보가 있는 경우 동의를 철회할 수 있습니다.
2. 권리 행사는 제14조의 연락처로 요청할 수 있습니다. 서비스가 보관하는 식별자는 Discord 사용자 ID이므로, 운영자는 요청한 사람이 해당 Discord 계정의 주인인지 확인합니다. 【확인 필요: 본인 확인의 구체적 방법】
3. 운영자는 요청을 받은 날부터 10일 이내에 조치하고 결과를 알립니다. 기간 안에 처리할 수 없는 정당한 사유가 있으면 그 사유와 처리 예정 범위를 알립니다.
4. 법정대리인이나 위임을 받은 사람도 권리를 행사할 수 있으며, 이 경우 위임 사실을 확인할 수 있는 자료를 제출해야 합니다.
5. 다음의 경우 삭제나 처리정지가 제한될 수 있으며, 운영자는 그 사유를 알립니다.
   - 법령에서 보존하도록 정한 경우
   - 다른 사람의 생명·신체·재산이나 권리를 부당하게 침해할 우려가 있는 경우
   - 진행 중인 보안 사건의 대응이나 분쟁 해결에 그 기록이 필요한 경우 【법률 검토 필요: 이 사유의 인정 범위】
6. 서비스에는 이용자가 직접 자신의 기록을 내려받거나 삭제하는 기능이 없으므로, 모든 요청은 운영자가 직접 처리합니다.
7. 서버 소유자는 서버에서 서비스를 제거한 뒤 그 서버 기록의 삭제를 요청할 수 있습니다.

# Sentinel 개인정보처리방침

**최종 수정일:** 2026년 11월 9일

**시행일:** 본 방침은 공개한 날부터 시행합니다.

---

Sentinel(이하 "**본 서비스**")을 운영하는 노아소프트(이하 "**운영자**")는 이용자의 개인정보를 소중히 여기며 **개인정보보호법** 및 관련 법규를 준수합니다. 용어는 [이용약관](https://noahsoft.kr/tos/sentinel/tos) 제1조를 따릅니다.

**본 서비스**는 보안 플랫폼입니다. 그래서 **본 서비스**를 직접 추가하지 않은 **서버 멤버**의 정보도, 서버 관리자가 **본 서비스**를 추가한 서버 안에서 처리됩니다.

---

## 1. 수집하는 개인정보 항목

이용하는 기능과 서버 관리자의 설정에 따라 처리 항목이 달라집니다.

### 1-1. 보안 이벤트·사건 (서버 멤버 포함)

* **행위자·대상 정보:** Discord 사용자 ID, 행위자의 역할 ID와 권한
  * Discord 감사 로그로 확인된 행위자는 "확인된 행위자"로 기록합니다.
  * 감사 로그로 확인되지 않았지만 정황상 가능성이 있는 사람은 **"추정 행위자"** 로 따로 기록할 수 있습니다. 추정 행위자에게는 자동 조치를 하지 않으며, 알림에만 표시합니다.
* **멤버 상태:** 사용자 ID, 봇 여부, 역할 ID, 타임아웃 종료 시각, 서버 입장 시각, 계정 생성 시각, 멤버 인증 대기 여부, 맞춤 아바타 사용 여부
* **초대 정보:** 입장 시 사용한 초대 코드, 초대 링크를 만든 사람의 ID
* **Discord 감사 로그 사본:** 실행자 ID, 대상 ID, 변경 전후 값, 감사 로그 사유 문구
  * 사유는 서버 관리자 등이 직접 입력한 자유 문구이며, 최대 512자까지 저장합니다.
  * 닉네임은 저장하지 않습니다.
* **사건·대응 기록:** 사건의 주요 행위자, 위험도 평가, 실행한 조치와 그 대상(타임아웃·역할 제거·격리 대상의 사용자 ID, 제거 전 역할 ID), 사건 상태 변경자

### 1-2. 메시지

* **메시지 본문은 저장하지 않습니다.**
* **처리하는 정보(모든 서버):** 스팸 탐지를 위해 다음 정보를 처리합니다.
  * 메시지 ID, 채널 ID, 작성자 ID, 작성자 역할 ID, 멘션 수, 작성자의 서버 입장 시각
  * 메시지 내용에서 만든 값: 정규화한 내용의 해시값(SHA-256)과 길이, 링크(도메인과 경로)의 해시값, Discord 초대 코드, `@everyone`·`@here` 사용 여부. 현재 **본 서비스**는 이 값을 만들기 위해 메시지 내용에 접근하며, 값을 만든 즉시 원문을 버립니다.
  * 위 정보는 탐지에 필요한 짧은 시간 동안(기본 약 10분, 서버 설정에 따라 최대 12시간) 서버 메모리에서만 처리하고 데이터베이스에 저장하지 않습니다.
* **스팸으로 탐지된 경우 저장하는 정보:** 작성자 ID, 탐지 종류, 요약(메시지 수·채널 수·참여자 수), 내용 또는 링크의 해시값. 메시지 ID, 메시지 내용, 초대 코드는 탐지 기록에 저장하지 않습니다.
* **해시값의 한계:** 위 해시값은 비밀 키 없이 만든 값입니다. 원문을 그대로 보여 주지는 않지만, 짧거나 흔한 문장·링크는 해시값으로부터 원문을 추정할 수 있습니다. 그래서 이 값을 익명 정보로 보지 않고 개인정보로 다룹니다.
* **AutoMod 실행 기록:** Discord AutoMod가 메시지를 차단하면, 대상 사용자 ID, 메시지 ID, 채널 ID, 규칙 종류와 조치 종류를 보안 이벤트로 기록합니다. 차단된 메시지의 내용과 일치한 키워드는 저장하지 않습니다.
* **스팸 탐지는 AI가 아닙니다.** 스팸 탐지는 정해진 규칙(같은 내용 반복, 대량 멘션 등)으로만 판단합니다. 메시지를 AI로 자동 분석하거나 욕설·비속어를 AI로 검사하는 기능은 현재 제공하지 않습니다.

### 1-3. 입장 관리·인증 (신규 입장자)

* **입장·인증 상태:** 상태와 변경 이력, 인증 방법, 퇴장·격리 시각, 인증 실패 횟수, 최근 위험 점수와 등급
* **인증 시도 기록:** 웹 인증 토큰의 해시값, 정답의 해시값. 토큰 원문과 이용자가 제출한 답은 저장하지 않습니다.
* **사용자 이름의 "형태" 해시값:** 비슷한 이름으로 몰려오는 계정을 찾는 데 씁니다. 표시 이름(없으면 사용자 이름)에서 숫자·기호를 단순화한 "형태"를 비밀 키 없이 해시(SHA-256)한 값이며, 이름 원문은 저장하지 않습니다. 흔한 이름은 해시값으로부터 형태를 추정할 수 있으므로 개인정보로 다룹니다.
* **차단 목록:** 서버 관리자가 등록한 사용자 ID와 사유
* **신고 기록:** 신고자 ID, 신고 대상 ID, 메시지 ID, 채널 ID, 분류, 처리 메모. **신고된 메시지 내용은 저장하지 않습니다.**
* **초대 게이트 통과 기록:** 사용자 ID, 부여할 역할 ID, 판단 사유
* **초대 게이트 로그인 권한:** Discord에 `identify`(사용자 ID)와 `guilds.join`(서버 입장 처리) 권한을 요청합니다. 아래 외부 신호가 켜진 경우에만 `guilds`(가입 서버 목록)를 추가로 요청합니다. 이메일 권한(`email`)은 요청하지 않습니다.
* **초대 게이트 외부 신호(서버 관리자가 켠 경우에만):** 초대 게이트 로그인 시 이용자의 Discord 가입 서버 목록을 확인합니다. 그중 서버 관리자가 지정한 차단 대상 서버와 겹치는 **개수만** 기록하며, 가입 서버 목록 자체는 저장하지 않습니다.

### 1-4. 서버 구조 스냅샷·증거

* **스냅샷:** 역할·채널(채널 주제 문구 포함)·권한 설정·AutoMod 규칙·서버 설정(서버 소유자 ID 포함). 멤버별 권한 덮어쓰기가 있으면 해당 멤버의 사용자 ID가 포함됩니다.
* **사건 증거 패키지:** 위 기록에서 만든 사건 자료와 해시 체인. 표시 이름·프로필 정보·메시지 내용은 포함하지 않습니다.
* **증거 다운로드 링크:** 증거 패키지를 내려받는 일회용 링크의 해시값, 링크를 요청한 사람의 ID, 발급·만료·사용 시각
* **스냅샷 정리 기록:** 보존 기준에 따라 스냅샷이 자동 삭제될 때, 삭제된 스냅샷의 ID·종류·생성 시각, 적용된 보존 기준, 정리를 일으킨 작업자의 ID와 종류. 스냅샷 내용과 자유 문구는 남기지 않습니다.
* 메시지 기록, 멤버 목록과 멤버별 역할 배정, 초대 링크는 스냅샷 대상이 아닙니다.

### 1-5. 웹 대시보드·초대 게이트 로그인

* **로그인 정보:** Discord 사용자 ID와 서버별 권한 등급(소유자·관리자·서버 관리 권한 여부). 대시보드 로그인은 Discord에 `identify`와 `guilds` 권한만 요청합니다.
* **로그인 세션 기록:** 세션 해시값, 생성·만료 시각
* **Discord OAuth 토큰**
  * 대시보드 로그인용 토큰은 사용 직후 폐기하며 보관하지 않습니다.
  * 초대 게이트용 토큰은 서버 입장 처리에 필요한 동안만 암호화해 보관하고, 처리 후 폐기합니다.
* **IP 주소**
  * **본 서비스**의 프로그램은 IP 주소 원문을 데이터베이스나 서비스 로그에 저장하지 않습니다. 요청을 처리하는 동안 서버 메모리에서만 씁니다.
  * **웹 대시보드·초대 게이트·웹 인증:** 접속 IP 주소를 **운영자**만 가진 비밀 키로 해시(HMAC-SHA256)합니다. 이 해시값은 요청 횟수 제한(1분 단위, 메모리에서만)에 쓰고, 관리 감사 로그와 AI 분석 요청 기록에 저장합니다.
  * **Sentinel Edge·내부 관리 API:** 접속 IP 주소를 요청 횟수 제한을 위해 메모리에서만 씁니다. 다만 내부 관리 API에서 인증에 실패하면, IP 주소를 비밀 키 없이 해시(SHA-256)한 값의 앞 16자리와, IP 주소와 시각으로 만든 기록 식별자를 운영 감사 기록과 서비스 로그에 남깁니다. 이 값으로는 원래 IP 주소를 비교적 쉽게 추정할 수 있습니다. 내부 관리 API는 **운영자**의 관리 도구용이며, 이용자가 사용하는 화면이 아닙니다.
  * 웹 인증에서 Cloudflare가 직접 처리하는 IP 주소는 제6조 6-2를 확인해 주세요.
* 브라우저 정보(User-Agent)와 브라우저 지문은 **본 서비스**가 수집하지 않습니다.
* **이메일 주소:** **본 서비스**는 Discord 계정의 이메일을 요청하거나 저장하지 않으며, Noahsoft Account 로그인을 사용하지 않습니다. 이용자가 이메일로 문의하는 경우에만 1-9와 같이 처리합니다.

### 1-6. 관리 활동·AI 분석

* **관리 감사 로그:** 명령·대시보드·**운영자** 내부 도구로 작업한 사람의 ID, 작업 내용, 대상, 결과, IP 해시값. 작업 내용에는 다음이 포함될 수 있습니다.
  * 작업 대상 사용자의 ID(차단 목록 등록, 관리 권한 부여·회수, 입장 상태 변경 등)
  * 서버 관리자가 입력한 문구(차단 사유, 신고 처리 메모, 복구 요청 사유)
  * 변경한 정책 내용(보호·신뢰 대상 사용자 ID 포함)
* **Sentinel 관리 권한 기록:** 권한 부여·회수 기록, 확인 절차 기록, 정책 변경 이력(변경자 포함), 복구 계획·실행 요청자와 승인자
* **AI 분석 요청 기록:** 요청자 ID와 역할 등급, 질문(민감정보 마스킹 후 최대 500자)과 그 해석 결과, 사용한 분석 도구, IP 해시값
* **AI 분석 결과:** 분석 결과와 요청자 ID
* **AI 사용량:** 서버 ID, 기능, 모델, 처리량, 응답 시간. 요청자는 기록하지 않습니다.
* **AI로 보내고 받은 원본:** 분석에 보낸 원본 프롬프트, AI 제공업체의 원본 응답, 관리자가 분류를 위해 붙여 넣은 메시지 원문은 저장하지 않습니다. 같은 메시지를 다시 분류하지 않도록, 메시지 ID와 붙여 넣은 내용의 해시값은 결과와 함께 보관합니다.

### 1-7. Sentinel Edge

**Sentinel Core에 저장되는 정보**

* Edge 장치 정보: 장치 ID, 공개키와 지문, Edge 봇의 사용자 ID, 승인·폐기한 사람의 ID, 최근 접속 시각
* Edge가 업로드한 보안 기록과 Edge가 실행한 조치 기록: 위 1-1과 같은 종류의 정보
* 상태 신호: Edge의 동작 상태와 버전 등 운영 정보. 개인정보는 포함하지 않습니다.

**고객 호스트에 저장되는 정보**

* 보안 이벤트, 행위자·대상 ID, 감사 로그 사유 문구, 채널·역할 이름, 멤버 상태
* 사용자 이름은 원문이 아닌 "형태" 해시값으로만 기록합니다.
* Edge는 메시지 내용을 수집하지 않습니다.
* Sentinel Core가 보낸 서명된 정책. 서버 관리자가 지정한 보호·신뢰 대상 사용자 ID가 들어 있습니다.

### 1-8. 서비스 로그

* 오류·보안 사고 대응을 위해 서비스 로그를 남깁니다. 로그에는 Discord 사용자 ID와 서버 ID, 처리 결과가 남을 수 있습니다.
* 토큰·비밀번호 등 비밀값은 가린 뒤 기록합니다. IP 주소 원문과 메시지 내용은 기록하지 않습니다. 단, 1-5의 내부 관리 API 인증 실패 기록은 예외입니다.

### 1-9. 문의

* 이메일 또는 Noahsoft Discord 서버로 문의하면, 회신과 요청 처리를 위해 이메일 주소(또는 Discord 계정)와 문의 내용을 처리합니다.

## 2. 개인정보 이용 목적

1. 서버 파괴 행위·대량 입장 공격·스팸 탐지와 대응
2. 신규 입장자 인증과 위험도 평가
3. 서버 구조 기록과 서버 관리자 승인 기반 복구
4. 사건 기록, 증거 패키지 생성, 사건 사후 분석(AI 분석 포함)
5. 서버 관리자 인증과 권한 확인, 관리 작업의 감사 기록
6. Sentinel Edge 연동과 장애 기간 기록의 대조·반영
7. 오류·보안 사고 대응과 문의 응대

---

## 3. 개인정보 보유 기간

기록은 성격에 따라 **일반 운영 기록**과 **보안·감사·증거 기록**으로 나누어 보관합니다. 아래 기간보다 처리 목적이 먼저 끝나는 기록(3-3)은 그때 지우고, 적법한 삭제 요구가 있으면 제7조에 따라 기간이 끝나기 전에도 처리합니다.

### 3-1. 일반 운영 기록

**본 서비스**를 서버에서 제거하면, 그 서버의 일반 운영 기록을 **제거 후 30일 이내**에 자동으로 파기합니다. 30일은 실수로 **본 서비스**를 제거했다가 다시 추가하는 경우를 위한 유예 기간입니다.

* **대상:** 보안 이벤트, Discord 감사 로그 사본, 메시지 해시값 기반 스팸 탐지 기록, 사건·위험 평가·대응 기록, 입장·인증 상태와 기록, 초대 게이트 통과 기록, 차단 목록, 신고 기록, 외부 신호 기록, 서버 구조 스냅샷(고정·연결된 스냅샷 포함), 복구 계획·실행 기록, AI 분석 결과·사용량, 서버 정책, 현재 **Sentinel 관리 권한** 부여 상태, Sentinel Edge 연동 설정과 조치 기록, 증거 다운로드 링크
* **예외:** 위 기록 중 관리 작업으로 남은 사본(차단 사유, 신고 처리 메모, 관리 권한 부여·회수 내역, 복구 요청자·승인자 등)은 3-2의 관리 감사 로그에 남으며, 정책 변경 이력은 3-2의 기준을 따릅니다.
* **늦게 들어온 기록:** 파기 뒤에 Sentinel Edge 업로드 등으로 늦게 들어온 기록은, 파기를 마친 서버를 주기적으로 다시 확인하는 정리 작업(보통 하루에 한 번 이상)에서 파기합니다.
* **제거를 확인하는 방법:** Discord가 **본 서비스**가 서버에서 제거(추방·제거·서버 삭제)되었다고 알린 시점부터 셉니다. Discord 장애로 서버가 일시적으로 보이지 않는 경우는 제거로 보지 않습니다.
* **다시 추가한 경우:** 파기 전에 **본 서비스**를 같은 서버에 다시 추가하면, 남아 있는 기록은 파기하지 않고 계속 사용합니다.
* **늦게 확인한 제거:** **본 서비스**가 중단된 동안 제거된 서버나 제거 알림을 기록하지 못한 서버는, **본 서비스**가 다시 연결된 뒤 이전에 있던 서버 목록과 비교해 찾아냅니다. 이 경우 제거를 확인한 시점부터 기간을 셉니다. 자동으로 찾지 못한 경우(예: 이 기능이 도입되기 전에 제거된 서버)에는 서버 관리자가 알려 주시면 **운영자**가 확인 후 파기를 진행합니다.
* **본 서비스가 서버에 있는 동안:** 3-3의 자동 정리 대상을 제외한 일반 운영 기록은 **본 서비스**를 서버에서 제거하거나 삭제를 요청할 때까지 보관합니다.

* **고객 직접 삭제:** 고객 호스트의 격리 기록과 연결 해제 후 남은 데이터는 자동으로 삭제되지 않으므로, 고객이 직접 삭제해야 합니다.

## 4. 개인정보를 볼 수 있는 사람

* **서버 관리자:** 자신이 관리하는 서버의 보안 이벤트, 사건, 멤버 입장 기록, 증거 패키지를 조회하고 내보낼 수 있습니다. 내보낸 증거 패키지는 해당 서버 관리자가 관리합니다.
* **고객의 Sentinel Edge:** Sentinel Core는 연결된 Edge에 서명된 정책을 보냅니다. 이 정책에는 보호·신뢰 대상 사용자 ID가 들어 있으며, **고객**의 호스트에 저장됩니다.
* **운영자:** 이용약관 제6조의 경우에 내부 관리 도구로 기록을 조회·변경할 수 있으며, 그 작업은 관리 감사 로그에 남습니다. 제7조의 요청을 처리하기 위해 **운영자**가 데이터베이스를 직접 다루는 경우는 관리 감사 로그에 남지 않으며, 처리 결과는 요청한 분께 알려 드립니다.
* **그 밖의 제3자:** 수집된 개인정보는 위 사람들과 제6조의 외부 업체 외의 제3자에게 제공하지 않습니다.
* **국가기관 등의 요청:** 수사기관 등 국가기관이 법령에 정해진 권한과 절차(영장 등)에 따라 요청한 경우에 한해, 요청 범위 안에서 제공할 수 있습니다. 법령상 근거나 절차가 확인되지 않은 요청에는 응하지 않습니다.

## 5. 자동화된 결정

**본 서비스**는 서버 관리자가 자동 조치를 켠 서버에서, 사람의 개입 없이 정해진 규칙으로 서버 멤버에게 조치를 할 수 있습니다. 조치에는 타임아웃, 위험 권한 역할 제거, 격리·미인증 역할 부여가 있습니다. **차단·추방은 하지 않습니다.**

### 판단 기준

* **서버 파괴 행위(Anti-Nuke)**
  * 짧은 시간 안의 대량 채널·역할·웹후크 삭제나 그 조합
  * 위험 권한 부여, 권한 상승 후 파괴 행위
  * 위험 권한을 가진 봇 추가
  * 서버 보안 설정 변경
  * 행위자는 Discord 감사 로그로 확인된 경우에만 조치 대상이 됩니다.
  * 정책 수준이 높으면(격리 단계), 행위자에게서 위험 권한을 받은 계정과 사건 중 추가된 봇도 격리 대상이 될 수 있습니다.
* **신규 입장자(입장 관리)**
  * 계정 생성 후 경과 시간, 아바타 유무, 비슷한 이름의 동시 입장
  * 차단 목록 등록 여부, 이전 사건·격리 이력, 인증 실패 횟수
  * 신고 이력, 외부 신호
  * 짧은 시간 안의 대량 입장
  * 신고와 외부 신호만으로는 조치하지 않으며, 다른 독립적인 신호가 함께 있어야 합니다.
* **스팸:** 같은 내용 반복, 링크·초대 링크 반복, 대량 멘션, `@everyone` 시도
* **AI 분석 결과는 판단에 쓰지 않습니다.**

각 요인의 점수와 임계값은 서버 관리자가 정한 정책(알림 전용·`balanced`·`strict`·`custom`)에 따릅니다.

### 설명 요구와 이의 제기

조치를 받은 서버 멤버는 다음 방법으로 조치의 근거 설명을 요구하거나 이의를 제기할 수 있습니다.

1. 해당 서버의 서버 관리자에게 요청하세요. 서버 관리자는 사건 기록에서 조치에 쓰인 요인을 확인할 수 있습니다.
2. 서버 관리자가 해결해 주지 않으면 아래 문의처로 **운영자**에게 요청할 수 있습니다.

## 6. 처리위탁 및 국외 이전

**본 서비스**는 아래 기능을 위해 외부 업체를 이용합니다.

### 6-1. AI 분석: OpenAI, Anthropic

* **운영 상태:** 현재 제공 중인 기능입니다. 모든 서버에서 서버 관리자가 요청할 때만 동작합니다.
* **전송 시점과 방법:** 서버 관리자가 대시보드에서 AI 분석을 요청할 때, 그 요청마다 네트워크를 통해 API로 전송합니다. 모든 메시지나 사건을 자동으로 보내지 않습니다.
* **전송 항목:**
  * 분석 대상 사건의 기록. Discord ID와 기록 ID는 `U1`, `C2` 같은 별칭으로 바꾸어 보냅니다. 토큰, 웹후크 주소, 이메일, 전화번호, IP 주소, 카드번호는 가린 뒤 보냅니다.
  * 관리자의 질문(민감정보를 가린 뒤 최대 500자)
  * 관리자가 분류를 요청하며 붙여 넣은 메시지(최대 4,000자)
* **받는 자:** OpenAI, Anthropic
* **업체 소재 국가:** 미국
* **업체 측 보유 기간:** 각 업체의 API 데이터 정책과 계약 조건을 따릅니다. 실제 처리 지역도 마찬가지입니다.
* **본 서비스가 보관하는 범위:** 분석 결과만 제3조의 기간 동안 보관하며, 보낸 원본과 업체의 원본 응답은 보관하지 않습니다.

### 6-2. 웹 인증: Cloudflare Turnstile (Cloudflare, Inc.)

* **브라우저에서 일어나는 일:** 웹 인증 페이지를 열면 이용자의 브라우저가 Cloudflare의 인증 스크립트를 불러옵니다. 이때 브라우저가 Cloudflare에 직접 접속하므로, Cloudflare는 이용자의 IP 주소를 포함한 브라우저·접속 정보를 봇 여부 판단을 위해 직접 처리할 수 있습니다.
* **본 서비스가 보내는 정보:** 인증 결과 토큰만 Cloudflare에 보내 검증합니다. **본 서비스**의 서버는 이 검증 요청에 이용자의 IP 주소를 따로 담아 보내지 않습니다.
* **업체 소재 국가:** 미국
* **처리 방식:** Cloudflare의 개인정보 정책을 따릅니다.

### 6-3. 국외 이전을 원하지 않는 경우

* **AI 분석:** 서버 관리자가 AI 분석을 요청하지 않으면 전송되지 않습니다.
* **웹 인증:** 웹 인증 페이지를 이용하지 않으면 됩니다. 다만 서버 관리자가 웹 인증을 입장 조건으로 정한 서버에서는 해당 서버의 인증을 마칠 수 없을 수 있습니다.

외부 업체나 전송 항목이 바뀌면 실제 적용 전에 본 방침을 먼저 갱신합니다. 메시지를 AI로 자동 판정하는 기능(예: 욕설·비속어 검사)은 현재 제공하지 않으며, 도입하는 경우에도 적용 전에 본 방침을 먼저 갱신합니다.

## 7. 이용자 권리

이용자는 다음을 요청할 수 있습니다. **본 서비스**를 직접 추가하지 않은 서버 멤버도 직접 요청할 수 있습니다.

* 개인정보 열람
* 정정·삭제
* 처리 정지
* 제5조의 자동화된 결정에 대한 설명 요구와 거부
  * **운영자**가 특정 서버 멤버를 자동 조치에서 직접 제외하는 기능은 현재 없습니다. 처리 정지나 자동화된 결정 거부를 요청하면 **운영자**가 해당 서버의 서버 관리자에게 전달합니다. 서버 관리자는 그 멤버를 신뢰 대상으로 지정해 위험 점수를 낮추거나, 받은 조치를 해제할 수 있습니다. 신뢰 대상 지정은 점수를 낮출 뿐 자동 조치에서 완전히 제외하지는 않습니다. 서버 관리자가 응하지 않으면 그 결과와 남은 방법(해당 서버의 기록 삭제 요청 등)을 알려 드립니다.

**요청 방법**

* 아래 개인정보 보호책임자 이메일 또는 Noahsoft Discord 서버로 요청해 주세요.
* 본인 확인을 위해 Discord 계정 확인을 요청할 수 있습니다.
* 만 14세 미만 아동의 법정대리인 등 법정대리인도 정보주체를 대신해 요청할 수 있습니다.

**처리 기한과 방식**

* 요청은 언제든 접수합니다.
* 일반 운영 기록(제3조 3-1)은 요청 내용과 본인 여부를 확인한 뒤 **72시간 이내** 처리를 목표로 합니다. 늦어지는 경우 그 사유와 예상 처리 시점을 알려 드립니다.
* 현재 이용자가 직접 기록을 지우는 기능은 없습니다. **운영자**가 요청을 확인한 뒤 처리합니다.
  * **서버 단위 삭제:** **본 서비스**를 서버에서 제거한 뒤 요청하면, 30일을 기다리지 않고 해당 서버의 일반 운영 기록을 파기합니다.
  * **특정 사용자의 기록 삭제:** **본 서비스**가 남아 있는 서버의 특정 이용자 기록은 전용 기능이 없어, **운영자**가 데이터베이스에서 개별로 확인해 삭제합니다.

**처리할 수 없는 경우**

다음 경우에는 처리할 수 없는 범위와 사유를 안내합니다.

* 법령상 보존 의무가 있는 기록
* 제3조 3-2의 관리 감사 로그와 스냅샷 정리 기록(현재 삭제할 수 없음)
* 제3조 3-2의 증거 해시 체인·Edge 업로드 기록(제거 후 1년 시점에 서버 단위로 전체 파기)
* 진행 중인 보안 사건의 조사에 필요한 기록

**서버 관리자와 고객**

* 서버 관리자는 서버 단위 기록의 삭제를 요청할 수 있습니다.
* 서버 관리자가 이미 내보낸 증거 패키지는 해당 서버 관리자가 관리합니다.
* **고객** 호스트에 있는 Sentinel Edge 기록은 **운영자**가 접근할 수 없으므로 **고객**이 직접 삭제해야 합니다.

## 8. 개인정보 파기 절차 및 방법

* **자동 파기:** 제3조의 기간이 지난 기록은 1시간마다 실행되는 정리 작업이 운영 데이터베이스에서 삭제합니다. 증거 패키지 파일은 기록과 함께, 파기를 실행한 운영 서버에서 삭제합니다.
* **요청에 따른 파기:** 서버 단위 요청은 위 정리 작업으로, 특정 사용자 기록은 **운영자**가 데이터베이스에서 직접 삭제합니다.
* **파기 기록:** 정리 작업이 파기를 마치면 서버 ID와 항목별 삭제 건수만 관리 감사 로그에 남깁니다. 삭제한 내용은 남기지 않습니다.
* **삭제 후 남을 수 있는 정보:** 삭제한 기록은 **본 서비스**의 기능과 화면으로 다시 조회할 수 없습니다. 다만 데이터베이스 엔진의 내부 로그 등에는 엔진 설정에 따른 기간 동안 남아 있을 수 있습니다.

## 9. 개인정보의 안전성 확보 조치

* **원문 대신 해시값 저장:** 웹 인증 토큰, 인증 정답, 로그인 상태값, 세션, 페어링 코드, 내부 관리 도구 토큰
* **IP 주소:** 원문을 저장하지 않고, 비밀 키를 사용한 해시값(HMAC-SHA256)으로 저장합니다. 단, 제1조 1-5의 내부 관리 API 인증 실패 기록은 예외입니다.
* **암호화:** 일시적으로 보관하는 OAuth 토큰과 로그인 검증값은 AES-GCM으로 암호화합니다.
* **대시보드 세션**
  * 세션은 최대 12시간 유지됩니다.
  * 1시간 동안 사용이 없으면 만료됩니다.
  * 15분마다 갱신합니다.
  * Discord 권한 재확인 주기(30분)가 지나면 다시 로그인해야 할 수 있습니다.
* **CSRF 방어:** 모든 변경 요청에 적용합니다.
* **변조 방지:** 관리 감사 로그는 데이터베이스가 수정·삭제를 거부합니다. 증거 해시 체인과 Edge 업로드 기록은 해시 체인으로 변조 여부를 확인할 수 있습니다. 이 기록도 제3조 3-2의 기간이 지나면 서버 단위로 전체를 파기합니다(관리 감사 로그 제외).
* **로그 보호:** 서비스 로그에서 토큰 등 비밀값을 가립니다.
* **Sentinel Edge**
  * Edge 기록은 항목마다 AES-256-GCM으로 암호화해 저장합니다.
  * Sentinel Core와 주고받는 요청·응답은 Ed25519로 서명하고 검증합니다.
  * Sentinel Core와의 통신은 원칙적으로 HTTPS만 허용합니다. 같은 호스트 안의 통신이거나 **고객**이 명시적으로 허용한 경우는 예외입니다.

## 10. 쿠키

웹 대시보드와 초대 게이트는 로그인 유지를 위해 아래 쿠키를 사용합니다. 광고·분석용 쿠키는 사용하지 않습니다. 보안 연결에서는 쿠키 이름 앞에 `__Host-`가 붙습니다.

* `sentinel_session`: 로그인 세션, 최대 12시간
* `sentinel_login`, `sentinel_gate`: Discord 로그인 과정 보호, 10분

브라우저 설정으로 쿠키를 거부할 수 있으나, 이 경우 대시보드 로그인과 초대 게이트를 이용할 수 없습니다.

# Sentinel 이용약관

**최종 수정일:** 2026년 11월 9일

**시행일:** 본 약관은 공개한 날부터 시행합니다.

---

본 약관은 Sentinel(이하 "**본 서비스**")의 이용과 관련하여, **이용자**와 **본 서비스**를 운영하는 노아소프트(대표 김정현, 이하 "**운영자**") 간의 권리, 의무 및 책임 사항을 규정합니다.

---

## 1. 용어

* **Sentinel Core:** **운영자**가 운영하는 Sentinel 봇과 그 서버·데이터베이스입니다. 보안 이벤트 기록, 위험 판단, 자동 대응, 스냅샷·복구, 사건 관리를 담당합니다.
* **Sentinel Edge:** **고객**이 자신의 호스트에서 자신의 Discord 봇 애플리케이션으로 직접 실행하는 보조 노드입니다. Sentinel Core가 연결되지 않는 동안 보안 기록을 남기고, **고객**이 켠 경우에 한해 최소한의 방어 조치를 수행합니다.
* **서버 관리자:** **본 서비스**를 Discord 서버에 추가했거나, 서버 소유자로부터 **Sentinel 관리 권한**을 받아 **본 서비스**를 설정·운영하는 사람입니다.
* **Sentinel 관리 권한:** 서버 안에서 **본 서비스**의 명령·대시보드를 사용할 수 있는 권한입니다. 서버 소유자가 `/운영자 부여`·`/운영자 회수` 명령으로 관리합니다.
* **고객:** Sentinel Edge를 설치·실행하는 서버 관리자입니다.
* **서버 멤버:** **본 서비스**가 추가된 Discord 서버의 구성원입니다. **본 서비스**를 직접 추가하지 않았더라도, 서버 관리자의 설정에 따라 **본 서비스**의 기록·조치 대상이 될 수 있습니다.
* **이용자:** 서버 관리자, 서버 멤버, 웹 대시보드·초대 게이트(Invite Gate)·웹 인증 이용자, **고객**을 모두 포함합니다.

---

## 2. 서비스 개요

**본 서비스**는 Discord 서버를 위한 보안 플랫폼으로, 다음 기능을 포함합니다.

1. **Anti-Nuke:** 대량 채널·역할 삭제, 위험 권한 부여 등 서버 파괴 행위를 탐지하고 대응합니다.
2. **Anti-Raid / 입장 관리(Admission Control):** 신규 입장자의 위험도를 평가하고, 인증·격리·입장 잠금을 수행합니다. 스팸 탐지도 포함합니다.
3. **스냅샷·복구:** 서버 구조(역할·채널·권한·AutoMod 규칙 등)를 주기적으로 기록하고, 서버 관리자의 승인을 받아 복구를 시도합니다.
4. **사건·증거 관리:** 사건 기록과 변조 탐지가 가능한 증거 패키지를 만듭니다.
5. **AI 분석:** 서버 관리자가 요청하면 이미 기록된 사건을 요약·설명하고, 관리자가 붙여 넣은 의심 메시지를 분류합니다.
6. **Sentinel Edge 연동:** **고객**이 직접 운영하는 Edge와 연동해, Sentinel Core 장애 중의 보안 기록을 이어받습니다.

**본 서비스**는 현재 **개발 중인 무료 파일럿 서비스**입니다. 기능, 화면, 명령어, 기본 설정은 개발 과정에서 변경될 수 있습니다.

## 3. 무료 파일럿

1. **본 서비스**는 현재 무료로 제공되며, 이용 대가를 청구하지 않습니다.
2. **운영자**는 이용자의 별도 동의 없이 **본 서비스**를 유료로 전환하거나 요금을 청구하지 않습니다. 유료 상품을 도입하는 경우 요금과 조건을 사전에 고지하며, 유료 이용은 이용자가 별도로 신청한 경우에만 시작됩니다.
3. **본 서비스**는 가용성 보장(SLA)을 약정하지 않습니다.

## 4. 자동 조치와 그 한계

### 4-1. 기본 설정

* Anti-Nuke의 기본 설정은 **알림 전용**이고, 입장 관리의 기본 설정은 **관찰(observe)** 입니다.
* 자동 조치는 다음 경우에만 실행됩니다.
  * 서버 관리자가 정책을 `balanced`·`strict`·`custom`으로 바꾼 경우
  * 서버 관리자가 입장 단계 변경·입장 잠금 등을 직접 실행한 경우
* 복구는 기본적으로 **서버 관리자의 승인 없이는 실행되지 않습니다.** 자동 복구는 기본적으로 꺼져 있습니다.

### 4-2. 자동으로 할 수 있는 조치

자동 조치가 켜진 경우, **본 서비스**는 정책과 위험도에 따라 다음 조치를 할 수 있습니다.

* 행위자 타임아웃
* 사건 중 행위자가 만든 웹후크 삭제
* 위험 권한이 있는 역할 제거 및 격리 역할 부여
* 서버 초대 일시 중지(자동 만료)
* 정책이 허용한 경우, 하위 역할의 위험 권한 제거(이전 값 기록)
* 신규 입장자에게 미인증·격리·인증 역할 부여
* 입장 잠금 중 서버의 Discord 인증 수준 상향(정책이 허용한 경우)

**본 서비스는 어떤 자동 경로로도 차단(ban)이나 추방(kick)을 하지 않습니다.** 자동 판단 기준은 [개인정보처리방침](https://noahsoft.kr/tos/sentinel/pp) 제5조에 적혀 있습니다.

### 4-3. AI는 조치를 결정하지 않습니다

AI 분석 결과는 참고용입니다. AI는 위험 점수에 반영되지 않으며, Discord에 어떤 조치도 직접 실행할 수 없습니다. 자동 조치는 정해진 규칙에 따라서만 판단합니다.

### 4-4. 오탐과 이의 제기

자동 탐지는 오탐이 생길 수 있습니다. 정상적인 서버 멤버가 타임아웃·역할 제거·격리 등의 조치를 받을 수 있습니다.

* 조치를 받은 서버 멤버는 해당 서버의 관리자에게 해제를 요청할 수 있습니다.
* **조치를 되돌리는 순서:** 같은 사건이 진행 중이면, 서버 관리자가 되돌린 역할·권한을 **본 서비스**가 다시 제거할 수 있습니다. 그래서 다음 순서로 진행해 주세요.
  1. `/대응 중지`로 자동 대응을 멈춥니다.
  2. Discord에서 타임아웃 해제, 역할 재부여 등으로 조치를 되돌립니다.
  3. `/사건 오탐`으로 해당 사건을 오탐으로 기록합니다.
  4. `/대응 재개`로 자동 대응을 다시 켭니다.
* 서버 관리자가 해결해 주지 않거나 **본 서비스** 자체의 오동작이 의심되면 아래 문의처로 알려 주세요.

### 4-5. 복구의 한계

복구는 원래 상태를 그대로 되돌리는 것이 아니라, 기록된 스냅샷을 바탕으로 **가능한 범위에서 다시 만드는 것**입니다. 다음은 복구되지 않습니다.

* 삭제된 채널·역할의 원래 ID
* 메시지 기록
* 멤버별 역할 배정
* 초대 링크
* 연동(integration)·관리형 역할, 스레드
* 서버 소유권·MFA 설정
* **본 서비스**의 역할보다 위에 있는 역할

**본 서비스**에 필요한 Discord 권한이 없으면 해당 항목은 기록·복구 대상에서 빠지고 경고로 표시됩니다.

## 5. 서버 관리자의 책임

1. 서버 관리자는 **본 서비스**에 필요한 최소한의 Discord 권한만 부여해야 합니다. **본 서비스**는 Administrator 권한을 요구하지 않습니다.
2. 서버 관리자는 정책(자동 조치 수준, 보호·신뢰 대상, 복구 보존 기간 등)을 서버 상황에 맞게 설정해야 합니다.
3. 서버 소유자는 **Sentinel 관리 권한**을 누구에게 부여할지 관리해야 합니다.
4. 서버 관리자는 서버 멤버가 **본 서비스**의 기록·조치 대상이 될 수 있다는 사실을 서버 규칙이나 공지 등으로 알리는 것을 권장합니다.
5. 서버 관리자가 AI 분석에 의심 메시지를 붙여 넣는 경우, 분석에 필요한 범위의 내용만 입력해야 합니다. 붙여 넣은 내용은 [개인정보처리방침](https://noahsoft.kr/tos/sentinel/pp) 제6조에 적힌 AI 제공업체로 전송됩니다.

---

## 6. 운영자의 내부 관리 도구

1. **운영자**는 Sentinel Core를 관리하는 내부 도구로 모든 서버의 **본 서비스** 설정을 변경할 수 있습니다. 여기에는 다음이 포함됩니다.
   * 정책 변경
   * 자동 대응 중지·재개
   * **Sentinel 관리 권한** 부여·회수
   * Sentinel Edge 승인·폐기와 긴급 방어 설정
   * 복구 실행
2. **운영자**는 이 도구를 다음 경우에만 사용합니다.
   * 해당 서버의 서버 소유자 또는 **Sentinel 관리 권한**을 가진 사람이 요청한 경우
   * 진행 중인 보안 사고나 **본 서비스**의 오동작에 긴급히 대응해야 하는 경우
   * 법령상 의무를 이행해야 하는 경우(국가기관 등의 요청은 법령에 정해진 권한과 절차에 따른 경우로 한정)
3. 이 도구로 한 작업은 모두 관리 감사 로그에 기록됩니다.
4. **운영자**가 요청 없이 이 도구를 사용한 경우에는, 작업 후 지체 없이 해당 서버의 서버 관리자에게 작업 내용과 사유를 알립니다.

## 7. Sentinel Edge

1. **운영 주체:** Sentinel Edge는 **고객**이 자신의 호스트에서, **고객**이 만든 Discord 봇 애플리케이션과 그 토큰으로 실행합니다. **운영자**는 **고객**의 호스트에 접근하지 않으며, **고객**의 봇 토큰과 마스터 키를 보관하지 않습니다.
2. **고객의 관리 책임:** **고객**은 Edge가 실행되는 호스트, Edge 봇 토큰, 마스터 키를 안전하게 관리해야 합니다. 호스트나 토큰이 탈취되면 공격자가 그 봇 권한으로 행동하거나, 아직 업로드되지 않은 기록을 바꿀 수 있습니다. 탈취가 의심되면 다음을 모두 해 주세요.
   * Edge 연결 해제(`/엣지 폐기`)
   * Discord 개발자 포털에서 Edge 봇 토큰 재발급, 또는 Edge 봇을 서버에서 추방
   * **운영자**에게 알림
3. **기본 동작:** Edge의 기본 모드는 기록 전용(`RECORDER`)이며, 스스로 조치하지 않습니다.
4. **긴급 방어(Emergency Guard):** 다음 조건을 모두 갖춘 경우에만 동작합니다.
   * **고객**이 호스트 설정에서 긴급 방어 모드를 켬
   * **Sentinel 관리 권한**과 Discord 서버 소유자 또는 Administrator 권한을 가진 사람이 긴급 방어를 켬. 제6조의 경우에는 **운영자**가 켤 수도 있습니다.
   * Sentinel Core에 일정 시간(기본 약 90초) 이상 연결되지 않음

   긴급 방어가 할 수 있는 조치는 다음뿐입니다.
   * 위험 역할 제거(이전 역할 기록)
   * 타임아웃(자동 만료)
   * 사건 중 생성된 웹후크 삭제
   * 초대 일시 중지(자동 만료)

   **차단·추방, 채널·역할 삭제, 역할 권한 변경은 하지 않습니다.** 제거된 역할은 자동으로 다시 부여되지 않으므로, 필요하면 서버 관리자가 직접 되돌려야 합니다.
5. **업로드:** Edge는 기록을 서명해 Sentinel Core로 업로드합니다. Sentinel Core는 업로드된 기록을 검증한 뒤 보안 기록으로 반영하며, Edge가 보고한 내용임을 표시합니다.
6. **연결 해제:** **고객**은 대시보드 또는 `/엣지 폐기` 명령으로 Edge 연결을 해제할 수 있습니다. 해제된 Edge는 같은 식별자로 다시 연결할 수 없습니다.
   * **해제는 즉시 반영되지 않을 수 있습니다.** Edge가 Sentinel Core에 연결되지 않은 상태라면, 이미 받아 둔 정책이 만료될 때까지(기본 최대 7일) 긴급 방어를 계속할 수 있습니다. 그래서 탈취가 의심되면 제2항의 토큰 재발급 또는 봇 추방을 함께 해야 합니다.
   * **고객** 호스트에 남은 Edge 데이터는 **고객**이 직접 삭제합니다.
7. **소프트웨어 이용 허락:** Sentinel Edge 소프트웨어의 저작권은 **운영자**에게 있습니다.
   * **운영자**는 파일럿 참여를 승인한 **고객**에게, 파일럿 기간 동안 해당 **고객**의 Discord 서버를 보호하는 목적으로 Edge를 설치·실행할 수 있도록 허락합니다. 본 항은 Sentinel Edge 라이선스가 요구하는 **운영자**의 사전 서면 허락에 해당합니다.
   * 그 밖의 복제, 수정, 재배포, 제3자 제공에는 **운영자**의 별도 사전 서면 동의가 필요합니다.

## 8. 개인정보

**본 서비스**는 보안 기능 제공을 위해 다음 정보를 처리합니다.

* Discord ID와 서버·채널·역할 정보
* 보안 이벤트와 Discord 감사 로그 기록
* 메시지 메타데이터
* 서버 구조 스냅샷

**메시지 본문은 저장하지 않습니다.** 다만 스팸 탐지를 위해 메시지 내용을 해시값 등으로 바꾸어 처리합니다. 스팸 탐지는 정해진 규칙으로만 판단하며, 메시지를 AI로 자동 판정하지 않습니다.

외부 업체는 다음과 같이 이용합니다.

* AI 분석: **OpenAI**, **Anthropic**의 API
* 웹 인증: **Cloudflare Turnstile**

**본 서비스**를 서버에서 제거하면 그 서버의 일반 운영 기록은 제거 후 14일 이내에 자동으로 파기됩니다. 증거 기록은 제거 후 1년, 일부 감사 기록은 기록 후 1년이 지나면 파기되며, 관리 감사 로그(관리 작업 대상의 사용자 ID와 서버 관리자가 입력한 사유 등 포함)는 현재 삭제할 수 없습니다. 삭제는 언제든 요청할 수 있습니다. 구체적인 처리 항목, 보유 기간, 외부 전송, 삭제 요청 방법은 [개인정보처리방침](https://noahsoft.kr/tos/sentinel/pp)을 확인해 주세요.

## 9. 금지 행위

* **본 서비스** 또는 Sentinel Core 서버를 공격하거나, 과부하를 일으킬 목적으로 요청을 반복하는 행위
* 웹 인증·초대 게이트를 자동화 도구 등으로 우회하는 행위
* 다른 사람의 계정·권한을 도용해 **본 서비스**를 설정하거나 명령을 실행하는 행위
* 허위 신고를 반복하거나, **본 서비스**를 특정 서버 멤버를 괴롭히는 수단으로 쓰는 행위
* 승인 없이 Sentinel Edge 소프트웨어를 복제·수정·재배포하는 행위
* **본 서비스**의 취약점을 발견하고도 알리지 않고 악용하는 행위

## 10. 이용 제한

1. **제한 대상:** 이용 제한은 제9조를 위반한 **본인**에게 적용합니다.
   * 서버 전체에 대한 이용 제한은 그 서버의 서버 관리자가 위반한 경우에만 합니다.
   * 외부인이 서버를 공격하거나 인증을 우회한 경우, 피해를 받은 서버는 제한하지 않습니다.
2. **일반 절차:** **운영자**는 먼저 위반 내용과 시정 방법을 알리고, 시정되지 않으면 이용을 제한할 수 있습니다.
3. **즉시 제한:** 다음의 **명백한 부정행위**로 **본 서비스**나 다른 이용자에게 즉각적인 피해가 생기는 경우에는, 사전 통지 없이 바로 제한할 수 있습니다. 이 경우 제한 후 지체 없이 사유를 알립니다.
   * Sentinel Core 서버에 대한 공격
   * 웹 인증·초대 게이트의 자동화 우회
   * 계정·권한 도용
4. **서버 단위 제한 시 통지:** 서버 단위로 이용이 제한되면 그 서버에 대한 보호 기능도 함께 멈춥니다. **운영자**는 서버 관리자가 다른 보호 수단을 마련할 수 있도록 제한 사실을 알립니다.
5. **이의 제기:** 이용자는 제한 조치에 대해 아래 문의처로 이의를 제기할 수 있으며, **운영자**는 이를 검토해 결과를 알립니다.

## 11. 서비스 변경·중단·종료

1. **운영자**는 개발 과정에서 기능, 기본 설정, 명령어를 변경할 수 있습니다. 자동 조치나 데이터 처리 방식처럼 이용자에게 영향이 큰 변경은 제13조에 따라 사전에 고지합니다.
2. 점검이나 장애로 **본 서비스**가 일시적으로 중단될 수 있습니다. Sentinel Core가 중단된 동안에는 실시간 탐지·자동 대응이 동작하지 않습니다. 단, 연동된 Sentinel Edge가 있으면 Edge가 기록을 이어갑니다.
3. 파일럿을 종료하는 경우 최소 30일 전에 고지합니다. 불가피한 사유로 사전 고지가 어려운 경우에는 사후에 지체 없이 알립니다.

1. **본 서비스**는 보안 사고 피해를 줄이는 도구이며, 모든 공격의 탐지나 피해 방지를 보장하지 않습니다. 다음과 같은 이유로 탐지·대응·복구가 이루어지지 않을 수 있습니다.

   * 서버 관리자의 권한·정책 설정
